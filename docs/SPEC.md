# 推し活カウントダウン Android 版 仕様

推し活の予定（推しのライブ・誕生日・発売日など）を登録し、その日まであと何日かを数えるアプリ。
画面デザインの正はデザインキャンバス「推し活カウントダウン 画面デザイン」の Android の 2 枚（ホーム、ウィジェット・通知）と iOS の主要画面 4 枚。
部品と操作感は iOS の画面をコピーせず Material 3 の標準に従い、デザインから引き継ぐのは機能・文言・配色だけにする。
iOS 版は、配色・書体・角の丸み・装飾をデザインキャンバスから独自のテーマ「地雷系・ゴシック」に置き換えた（[5. iOS 版のテーマ](#5-ios-版のテーマ)）。Android 版の配色はデザインキャンバスのまま。
実装の構成は [`architecture.md`](architecture.md)。

## 2. 画面

### 2.1 初回の導線

設定の「導線を終えた」が保存されるまで、タブの代わりに出す。

1. **ステップ 1 / 2：推しの登録**（推しの登録・編集の画面）。「次へ：最初の予定を登録」で登録して次へ。上の「あとで」で登録せずに次へ
2. **ステップ 2 / 2：最初の予定**（予定の追加の画面）。登録したばかりの推しを選んでおく。「保存してはじめる」で保存してタブへ。上の「あとで」で保存せずにタブへ

2 歩目から 1 歩目には戻らない（登録した推しを同じ画面でもう一度登録させないため）。

### 2.2 タブ

ホーム・推し・設定の 3 つ。M3 の基準で、電話はナビゲーションバー、広いウィンドウはナビゲーションレール。
詳細・入力の画面を開いている間はナビゲーションを隠す。

### 2.3 ホーム

- 見出し「推し活カウントダウン」
- 推しの絞り込み（「すべて」と推しごとの `FilterChip`）。推しが 1 人もいなければ出さない
- **先頭の予定のカード**：推し色の塗りに白い文字。ピン留めした予定（終わっていなければ）、無ければいちばん近い予定。「ピン留め」/「いちばん近い予定」、推しの名前、タイトル、「あと N 日」、日付（`10.18 SUN`）、開始の時刻（`開演 17:00`）
- **これからの予定**：当日とこれからの予定を近い順。行は推しのアバター（写真か頭文字）、タイトル、「日付 · 推しの名前」（毎年くり返す予定は「· 毎年」）、残り日数を推し色で
- **終わった予定**：設定で ON のときだけ。新しい順に「N 日前」
- 右下の「予定を追加」
- 予定が 1 件も無いときは案内と「予定を追加」

### 2.4 予定の詳細

- 推しの写真（無ければ推し色の斜めの縞）を上に敷き、中身のカードを重ねる
- 種類・推しの名前・タイトル
- 「開演まで」（時刻が無ければ「当日まで」）と、残りの日数（大きく）・時:分:秒（1 秒ごとに進む）
- 当日の開始の時刻を過ぎたら「今日は当日！」、終わった予定は「終わった予定」「N 日前」
- 進み具合のバー：登録した日（毎年くり返す予定は前の回のほうが後ならその日）から当日まで。「登録 9/2」「76% 経過」「当日 10/18」
- 日時・会場・くり返し
- 上のボタン：戻る、ピン留めの切り替え、編集、その他（予定を削除。確認のダイアログを出す）

### 2.5 予定の追加・編集

全画面のダイアログ（M3）。閉じる・見出し・保存。

| 項目 | 内容 |
|---|---|
| 推し | 推しごとのチップと「推しなし」。追加では先頭の推しを選んでおく |
| 種類 | ライブ・誕生日・発売日・配信・その他。誕生日を選ぶと「毎年くり返す」を ON、ほかの種類を選ぶと OFF（あとから切り替えられる） |
| タイトル | 必須。40 文字まで |
| 日付 | M3 の `DatePicker`。追加では今日 |
| 開始時刻 | 任意。M3 の `TimePicker`（24 時間表記）。初めて選ぶときは 18:00 から。消すボタンで時刻なしに戻す |
| 会場・場所 | 任意。40 文字まで |
| 毎年くり返す | 誕生日・記念日向け |

### 2.6 推しの一覧と登録・編集

- 一覧：登録した順に、アバター・名前・予定の件数。押すと編集、右下の「推しを登録」で登録
- 登録・編集：写真（Photo Picker。写真を変える・外す）、名前（必須。20 文字まで）、推し色（12 色から 1 つ）、「写真と推し色はこの端末の中だけに保存されます」
- 削除（編集のときだけ）：確認のダイアログに、一緒に消える予定の件数を出す。推しと、結び付いた予定と、写真を消す

### 2.7 設定

- 終わった予定も表示する（既定は OFF）
- 通知（[2.9 通知](#29-通知)）: 予定を通知する（既定は ON）、タイミングごとの切り替え（30 日前・7 日前・前日・当日・開演 1 時間前。既定はすべて ON）、通知の時刻（既定 9:00）。
  「予定を通知する」が OFF のときは、タイミングと時刻の項目を隠す。
  通知が許可されていなければ「通知が許可されていません。…」と、端末の設定のこのアプリの通知の画面を開くボタン「設定を開く」を出す。まだ許可を聞いていなければ「通知を許可する」を出す
- データの保存先の説明（端末の外に送らない、アプリを削除すると消える）
- このアプリについて
  - バージョン（`versionName`）
  - オープンソースライセンス：押すとアプリで使っているライブラリの一覧（名前・作者・バージョン・ライセンス）を開く。行を押すとライセンスの本文を出す

### 2.8 ホーム画面ウィジェット

端末のウィジェットの一覧から置く。色は端末の外観（ライト / ダーク）に合わせる。

- **カウントダウン**（2×2）：選んだ予定 1 件。推し色の塗りに白い文字で、推しの名前（推しなしの予定は種類）、タイトル、「あと N 日」。
  当日は「今日！」、終わった予定は「N 日前」。数字は桁が多い・ウィジェットが狭いときに小さくする
  - 置くときに「表示する予定を選ぶ」画面を出し、当日とこれからの予定から 1 件選ぶ。選ばずに閉じたら置かない。Android 12 以降は長押しで選び直せる
  - 押すとアプリで予定の詳細を開く
  - 選んだ予定が削除されたら「予定が見つかりません」「タップして予定を選び直す」。押すと選ぶ画面を開く
- **推しカウント**（4×2）：当日とこれからの予定を近い順に、推し色の丸・タイトル・残り日数（推し色。当日は「今日！」）。予定が無ければ「これからの予定はありません」
  - 行を押すとアプリで予定の詳細、右上の ＋ で予定の追加、見出しでアプリを開く
- アプリで開く画面はホームのタブに積む（ホームのタブは最初の画面まで戻す）。初回の導線の途中なら開かない

### 2.9 通知

予定の前に、端末の中で予約する通知（通信しない）。設定はアプリ全体で 1 つで、予定ごとには持たない。

- タイミング: 30 日前・7 日前・前日・当日は設定の時刻（既定 9:00）に、開演 1 時間前は開始の時刻の 1 時間前に出す（開始の時刻がある予定だけ）
- 文面
  - タイトル: 予定のタイトル
  - サブタイトル: 推しの名前（推しなしの予定は種類）。ウィジェットのカウントダウンと同じ
  - 本文: タイミングの文言に、前の日に出すものは開催日、開始の時刻があればそれを ` · ` で続ける
    （`あと 30 日 · 10月18日(日) · 開演 17:00`、`いよいよ明日！ · 10月18日(日) · 開演 17:00`、`今日！ · 開演 17:00`、`あと 1 時間 · 開演 17:00`）
- 許可: まだ聞いていなければ、予定を保存した直後と、設定で「予定を通知する」を ON にしたときに求める
- 押すと、アプリでその予定の詳細を開く（ウィジェットと同じく、ホームのタブに積む。初回の導線の途中なら開かない）
- アプリを開いている間に出た通知も、ふだんどおり出す

## 3. 規則

| 項目 | 規則 |
|---|---|
| 残り日数 | 端末のタイムゾーンでの暦の日数。当日は「今日！」 |
| 詳細の残り | 開始の時刻（無ければ開催日の 0:00）までの時間を、日（24 時間単位）と時:分:秒で |
| 毎年くり返す予定 | 登録した日付がまだ来ていなければその日、過ぎていれば今年か来年の同じ日（当日を含む）を数える。終わった予定にはならない。2/29 は平年には 2/28 |
| 終わった予定 | くり返さない予定で、開催日を過ぎたもの |
| 同じ日の並び | 時刻の無い予定（終日）、時刻の早い順、登録した順 |
| ピン留め | 1 件だけ。別の予定をピン留めすると前のピン留めは外れる |
| 日付が変わったとき | ホームは 1 分おきに日付を確かめ、変わったら数え直す。ウィジェットは 0:00 から 10 分以内と、端末の時刻・タイムゾーンを変えたときに数え直す |
| ウィジェットの描き直し | 推し・予定を保存・削除したらすぐ描き直す |
| 文字数 | 見た目の 1 文字（書記素クラスタ）で数える。連続する空白は 1 つに潰し、前後の空白は落とす |
| 写真 | 選んだ写真は長辺 1440px 以下の JPEG に縮めてアプリの内部ストレージに取り込む。差し替え・外す・推しの削除で前の写真を消す |
| 通知を出す日時 | 開催日（毎年くり返す予定はその回）から数えた日の、設定の時刻。開演 1 時間前は、開始の時刻から実際の経過時間で 1 時間前（夏時間をまたいでも 1 時間）。日付・時刻は書いたまま持ち、端末のタイムゾーンを変えても、その土地の同じ日付・時刻に出す |
| 当日の通知と開演 1 時間前 | 開始の時刻がある予定では、日付で決まる通知（30 日前・7 日前・前日・当日）は、開演 1 時間前（その通知を出さない設定なら開始の時刻）より前に出るものだけ出す。開演に間に合わない・開演 1 時間前と重なる・その後になる「当日」を出さない |
| 通知を出さないもの | 今より前の時刻のもの（予定の 10 日前に登録したら 30 日前は出さない）と、終わった予定 |
| 毎年くり返す予定の通知 | 次の回と、その次の回まで予約する（当日を過ぎてアプリを開かなくても、翌年の分が残るように）。2/29 は平年 2/28 |
| 通知の予約し直し | 推し・予定を保存・削除したとき、日付・時刻・タイムゾーンが変わったとき、アプリが前面に来たとき、通知の設定を変えたときに、上の規則で予約し直す。消した予定・過ぎた回・OFF にしたタイミングの予約は取り消す。許可されていなければ予約を残さない |
| 通知の数 | iOS はアプリごとに 64 件までしか予約できないので、近い順に 64 件（Android 版の上限は Android 側で決める） |
| 保存・削除の途中 | 画面を閉じない（閉じる・戻るを押せない） |
| 保存・削除の失敗 | 「保存できませんでした」「削除できませんでした」を Snackbar で出す。入力は残し、もう一度押せる |
| バックアップ | 自動バックアップと端末間の移行の対象にしない。機種変更では引き継がない |

## 4. デザインからの読み替え

| 項目 | デザイン | Android 版 |
|---|---|---|
| 書体 | Outfit（数字）+ Zen Kaku Gothic New | システムの既定の書体。数字は太字で桁の幅をそろえる（`tnum`。秒が進んでも横に揺れない） |
| 予定の追加 | iOS のシート（ガラス風） | M3 の全画面のダイアログ |
| 種類の選択 | iOS のセグメント | M3 の `FilterChip` |
| 推し色の選択 | 色の丸 | 同じ見た目で、ラジオボタンとして読み上げる。1 つ 48dp 以上 |

| ダークの外観 | デザインはライトだけ | M3 のダークの地。推し色を地の上の文字に使うときは白に 45% 寄せる（暗い推し色でも 4.5:1 を保つ） |

| 予定の通知の項目・ウィジェットの案内 | 予定の追加にあり | 置かない（通知は設定でアプリ全体に対して切り替える。ウィジェットは端末のウィジェットの一覧から置く） |

| 推しカウントの地 | 薄い灰色（`#F3EDF1`） | カードの地（ライトは白）。推し色の文字が 4.5:1 を保てる地にする |
| 推しカウントの ＋・行 | 32dp の丸、詰めた行 | ＋ は見た目の丸を 32dp のまま、押せる範囲を M3 の 48dp にする。行の高さも 48dp |

## 5. iOS 版のテーマ

iOS 版は [Discussion #80（アプリのテーマを改善する）](https://github.com/shariverse/oshikatsu-countdown-ios/discussions/80) で 5 つのテーマ案から「地雷系・ゴシック」を選び、出荷するアプリとウィジェットの見た目にした（[iOS #115](https://github.com/shariverse/oshikatsu-countdown-ios/pull/115)。develop への取り込みは [iOS #97](https://github.com/shariverse/oshikatsu-countdown-ios/pull/97)）。
**iOS 独自のテーマ**で、Android 版に入れるかは Android 側で決める。入れるまでは、Android 版は §4 のとおりデザインキャンバスの配色で作る。

- 変わったのは見た目（地の配色・書体・角の丸み・装飾）だけ。機能・文言・規則（§1〜§3）は変わらない
- 推し色は変えない。12 色の値と役割（先頭のカードの塗り・写真が無いときの模様の色・残り日数の文字・印）はそのまま
- 値の正は iOS の [`docs/design/themes.md`](https://github.com/shariverse/oshikatsu-countdown-ios/blob/2e2fb4bee9bd93fcb072d2df6acbd659162de504/docs/design/themes.md) と [`Shared/Design/Themes/JiraiGothic.swift`](https://github.com/shariverse/oshikatsu-countdown-ios/blob/2e2fb4bee9bd93fcb072d2df6acbd659162de504/Shared/Design/Themes/JiraiGothic.swift)（iOS の develop の 2e2fb4b）

### 5.1 狙い

黒 × ピンクで、ダークが主役。ライトも薄いピンクの地に黒の文字・黒の縁取りで、世界観が分かるようにする。日本語の本文は装飾的な明朝で、ゴシックの雰囲気を出す。

### 5.2 配色

役割の名前は Android 版の `OshikatsuColorScheme` と同じ（iOS のテーマには `outline` が無い）。

| 役割 | ライト | ダーク |
|---|---|---|
| background（画面の地） | `#FFF0F5` | `#120D12` |
| surface（カード・シート） | `#FFFFFF` | `#1E141C` |
| surfaceContainer（入力欄の地） | `#FBE4EE` | `#180F16` |
| surfaceContainerHigh（進み具合のバーの溝・区切り） | `#F0C9DA` | `#3A2533` |
| onSurface（本文） | `#1A0F16` | `#F6E6EE` |
| onSurfaceVariant（補助テキスト） | `#5A3A4C` | `#D6B9C8` |
| outlineVariant（区切り線） | `#E8B9CF` | `#5C3A4E` |
| brand / onBrand | `#C2185B` / `#FFFFFF` | `#FF7EB3` / `#3A0A20` |
| brandContainer / onBrandContainer（選択中の印の地と、その上の文字） | `#F8C8DC` / `#1A0F16` | `#6E1E45` / `#FFD9E8` |
| destructive（削除の文字） | `#B3261E` | `#F2B8B5` |
| ホームの地の十字・ハート | `#F2B6CF` | `#4A2A3C` |
| カードの二重の線 / 見出しのハート | `#1A0F16` / `#C2185B` | `#FF7EB3` / `#FF7EB3` |

推し色を地の上の文字に使うときの寄せ方:

- ライト: 画面の地・カードの地では黒に 8%、入力欄の地（surfaceContainer）では黒に 12% 寄せる（地が薄いピンクのため）
- ダーク: 白に 45% 寄せる（§4 のダークの外観と同じ）
- 推し色 12 色の文字は、画面の地・カードの地・入力欄の地のどれでも 4.5:1 以上（いちばん小さいのはライトがオレンジ・入力欄の 4.85、ダークがブラック・カードの 5.77）

### 5.3 書体

- 日本語の本文: Kaisei Decol（Regular / Bold。Medium は Regular に寄せ、合成の太字にしない）。ライセンスは SIL Open Font License 1.1（[google/fonts](https://github.com/google/fonts) の `ofl/kaiseidecol`）
- 数字: Outfit の Heavy（デザインキャンバスでは Bold）
- iOS 版も日本語のときだけ Kaisei Decol を使い、ほかの言語はシステムの書体にしている

### 5.4 角の丸み

| 部品 | iOS 版のテーマ | デザインキャンバス |
|---|---|---|
| ホームの先頭の予定のカード | 16 | 28 |
| 見出しつきのまとまり（これからの予定など） | 12 | 20 |
| 予定の詳細のカード（上の 2 つの角） | 20 | 28 |
| 種類などの小さな札 | 4 | 8 |

単位は iOS の pt。

### 5.5 装飾

- ホームの画面の地: 十字とハートを小さく散らす（不透明度 0.35）。同じ大きさの模様をくり返して敷くので、広い画面でも模様の密度は変わらない。推しの一覧・設定・予定と推しの編集・初回の導線の地は background の単色
- カードの縁: 二重の線（外側に 1.5pt、その 4pt 内側に 1pt。内側の線は不透明度 0.5）
- 見出しの前にハートを置く
- 写真が無いときの写真の場所（§2.4）: 推し色の斜めの縞の代わりに、推し色を黒に 30% 寄せた地に、白い十字とハート（不透明度 0.2）を互い違いに散らす
- 設定・予定と推しの編集・ライセンスの一覧の行の地も、カードの地（surface）にそろえた
- 装飾は図形と記号で描き、画像の素材は使わない。読み上げ・押せる範囲・並び順を変えず、カードの中の文字の上には重ねない
- ホーム画面ウィジェットに効くのは配色と書体だけで、装飾は入れていない

## 6. 有料の機能（推し活カウントダウン Plus）

iOS 版 1.3.0 で、有料の機能「推し活カウントダウン Plus」を入れる。Android 版にも入れる前提。
解放する機能の中身（画面・規則）は、iOS 版で作るたびにこの節に書き足す。

### 6.1 解放するもの

- 推しの写真ウィジェット: 予定の推しの写真を背景にしたカウントダウンのウィジェット（新しい種類として足す）
- 背景・飾りの着せ替え: アプリの画面の地に推しの写真を敷く・地の飾りを推しの丸い写真にする

今ある無料の機能（数える・ウィジェット・通知・ロック画面・当日の表示）は、有料に移さない。

### 6.2 売り方と価格

| 商品 | 価格（日本・税込み） | 内容 |
|---|---|---|
| 月額 | 280 円 | 自動で更新する定期購入 |
| 年額 | 1,980 円 | 自動で更新する定期購入。1 週間の無料のお試しつき（年額だけ） |
| 買い切り | 4,800 円 | 1 回の購入でずっと使える。今後足す Plus の機能も含む |

- Plus が使えるのは、定期購入が有効か、買い切りを買ったとき
- 解約・期限切れで見た目を標準に戻す。選んだ画像は消さずに残す（また入ったら戻る）
- 課金はストアの仕組みだけで行い、自前のサーバー・解析は使わない（通信しない方針はそのまま。購入の処理はストアが行う）
- アカウントが無いので、iOS と Android の購入は共有しない
- iOS 版はファミリー共有を OFF にした（一度 ON にすると戻せないため）
- iOS 版の商品 ID と、12 言語の表示名は [`docs/app-store/in-app-purchases.json`](https://github.com/shariverse/oshikatsu-countdown-ios/blob/a5d650197a156888a18446e250820906d389082d/docs/app-store/in-app-purchases.json)（iOS の develop の a5d6501）

### 6.3 Plus が使えるかの判定

- 月額か年額の定期購入が期限の前なら使える。期限を過ぎても、請求に失敗したときの猶予期間（iOS は Billing Grace Period を ON にする）の終わりの前なら使える
- 買い切りがあれば使える
- 返金・取り消しになったもの、期限切れのものは数えない。ストアが端末の中で検証できた購入だけを数える（通信はしない）
- 判定し直すのは、起動したとき・アプリが前面に来たとき（開いている間に期限を過ぎたとき）・ストアから購入の更新が届いたとき（ほかの端末での購入・更新・返金・承認待ちの承認）・購入と購入の復元のあと
- ウィジェットには、Plus が使えるかと期限を、アプリとウィジェットで共有する場所に書いて渡す。アプリを開かなくても、期限を過ぎたらウィジェットも Plus でない表示に戻る

### 6.4 課金画面

- タイトルは「推し活カウントダウン Plus」
- 上から、見出し → 定期購入（月額・年額）→ 買い切り → 購入の復元・利用規約・プライバシーポリシー の順に並べる
- 見出し: 「推しの写真で、ホーム画面とアプリをもっと自分らしく。」と、Plus の機能の一覧（記号と文。画像の素材は使わない）

| 機能 | 説明 |
|---|---|
| 推しの写真ウィジェット | ホーム画面に、推しの写真とカウントダウンを置けます |
| 背景と飾りの着せ替え | アプリの背景や飾りを、推しの写真で着せ替えられます |

- 見出しの下に「数える・ウィジェット・通知などの今ある機能は、これまでどおり無料で使えます」と添える。Plus が使える人には「Plus をお使いいただけます」を出す
- 買い切りの欄: 「買い切り」の見出しと、「一度の購入で、今後足す Plus の機能もずっと使えます」
- 購入の結果: 承認待ち（保護者の承認など）と失敗はダイアログで知らせる。自分で取り消したときは何も出さない
- 利用規約は、iOS 版では Apple の標準の使用許諾契約（EULA）を開く
- プライバシーポリシーは https://shilokuma.jp/privacy/oshikatsu-countdown/ を開く（ストアに登録するプライバシーポリシーの URL と同じ。iOS 版は URL を 1 か所の定数に置いた）
- 利用規約・プライバシーポリシーは、アプリから出ずに、アプリの中にブラウザの画面を重ねて開く。閉じると課金画面に戻る（購入の途中でアプリから離れないように）
  - ページを読み込むのはブラウザ（アプリとは別のプロセス）で、アプリは通信の中身や閲覧の情報に触れない。アプリが自分で読み込む WebView は使わない（通信しない方針と、プライバシーポリシーの記述のため）
  - iOS 版は `SFSafariViewController`（Safari の画面を全画面で重ね、「閉じる」で課金画面に戻る）。Android 版で当たるのは Custom Tabs
- iOS 版は標準の課金画面の部品（`SubscriptionStoreView`・`ProductView`）で組んだ。大きな文字・iPad・横向きでも崩れないようにした

### 6.5 定期購入中に買い切りを買う人への案内

買い切りを買っても、定期購入は自動で止まらない（請求が続く）ので、2 回伝える。

- 購入前: 自動で更新される定期購入がある間は、買い切りのそばに「サブスクリプション中に買い切りを購入しても、サブスクリプションは自動で止まりません。購入後に、ご自身で解約してください。」と出す
- 購入後: 自動で更新される定期購入があるまま買い切りを買い終えたら、「サブスクリプションの解約をお忘れなく」の案内を出し、そこから定期購入の管理を開けるようにする
- 解約済み（期限までは使えるが更新されない）・期限切れ・返金された定期購入は、請求が続かないので数えない

### 6.6 入口

- 設定画面の先頭に「推し活カウントダウン Plus」の行を置き、押すと課金画面を開く。説明は「推しの写真ウィジェットと、背景と飾りの着せ替え」。Plus が使える人には「Plus をお使いいただけます」
- Plus の機能（写真ウィジェット・着せ替え）ができるまでは、開発版と TestFlight（テスト配信）だけに入口を出し、App Store 版では出さない。機能が揃ったら、App Store 版でも出す
- 写真ウィジェット・着せ替えの画面からも、課金画面を開く（それぞれの機能を作るときに書き足す）
- App Store の製品ページでの課金の商品の宣伝（Promoted In-App Purchases）は、1.3.0 ではしない
